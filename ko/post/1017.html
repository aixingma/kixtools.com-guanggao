개발자 도구로 숨겨진 M3U8 주소 찾는 방법

게시 2026-10-18 · 약 4분 소요

목차

  1. Network 패널을 준비하는 순서
  2. 재생 목록 요청 걸러내기
  3. 후보 주소 검증하기
  4. 막히는 지점별 해법

Network 패널을 준비하는 순서

영상 주소는 소스 보기로는 보이지 않고, 플레이어가 재생을 시작할 때만 네트워크로 흐릅니다. 그래서 관건은 재생 버튼을 누르기 전에 도구를 열어 두는 것입니다.

  1. 대상 페이지에서 F12(또는 우클릭 → 검사)로 개발자 도구를 열고 Network 탭으로 이동합니다.
  2. Preserve log를 켭니다. 페이지가 새로고침되거나 이동해도 기록이 사라지지 않습니다.
  3. 기록이 비어 있는 상태에서 영상을 재생합니다. 요청이 차곡차곡 쌓이기 시작합니다.

재생 목록 요청 걸러내기

필터 상자에 m3u8을 입력하면 대부분의 경우 바로 잡힙니다. 결과가 비어 있다면 .ts나 .mp4로 검색해 보세요. 조각 요청이 보이면 그 Initiator(개시자)나 상위 경로를 따라 올라가면 재생 목록이 나옵니다. MIME 타입으로 구별하는 방법도 있습니다:

  • application/vnd.apple.mpegurl 또는 application/x-mpegURL — HLS 재생 목록 본체입니다.
  • video/mp2t — TS 조각입니다. 주소가 아니라 내용물이죠.

후보를 찾았다면 우클릭 → Copy → Copy link address로 주소를 복사합니다.

후보 주소 검증하기

복사한 주소를 새 탭에서 열어 응답 첫 줄을 확인하세요. #EXTM3U로 시작하면 재생 목록이 맞습니다. 내용에 따라 성격이 갈립니다:

#EXTM3U
#EXT-X-STREAM-INF:BANDWIDTH=2600000,RESOLUTION=1920x1080
1080p/index.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=1200000,RESOLUTION=1280x720
720p/index.m3u8

#EXT-X-STREAM-INF가 보이면 마스터입니다. 이 주소 자체보다 그 안에 적힌 하위 재생 목록 주소가 실제 재생 대상인 경우가 많습니다. #EXTINF와 TS 파일 목록만 나열되어 있으면 미디어 재생 목록이며, 바로 재생에 쓸 수 있는 주소입니다. 찾은 주소가 동작하는지는 온라인 플레이어에 붙여 넣어 보는 것이 가장 빠릅니다.

막히는 지점별 해법

  • 재생해도 m3u8 요청이 안 보임 — MSE 기반 플레이어는 요청이 스크립트에서 일어나므로, 필터를 지우고 Fetch/XHR 뷰에서 타입별로 정렬해 보세요.
  • 주소에 서명이 붙어 있음 — 쿼리의 token·expire 값은 수명이 짧습니다. 테스트 직전에 다시 복사하는 것이 안전합니다.
  • 콘솔에 CORS 오류 — 서버가 외부 재생을 허용하지 않는 상태입니다. 주소가 맞아도 다른 곳에서는 재생되지 않습니다.
  • 모바일 전용 스트림 — 데스크톱 Chrome의 기기 에뮬레이션으로 모바일 환경의 요청을 유도하면 잡히는 경우가 있습니다.

주소를 확보한 다음 단계가 궁금하면 튜토리얼의 변환·저장 편을 이어서 보고, 재생이 자꾸 버벅이면 원인별 점검 글을 참고하세요. 변환까지 바로 진행하려면 M3U8→MP4 변환 도구를 쓰면 됩니다.
