先弄清浏览器的真实底细

Chrome 与 Edge 的原生 <video> 标签并不认识 m3u8：既不会解析清单，也不会调度分片。Safari 是唯一的例外，苹果把整套 HLS 客户端内置进了浏览器。不过 Chrome/Edge 提供了 MSE（Media Source Extensions） 接口，允许脚本把媒体数据一段段喂给解码器——正是这道接口，撑起了网页端所有的 HLS 播放方案。

方案一：网页播放器，零配置

最省事的一条路。打开 M3U8Lab 在线播放器，粘贴地址即可开播，清单解析、码率切换、失败重试都已在内部处理妥当。临时看一条流、快速验证链接、或者嵌进自己的页面，它都够用；代价是必须遵守浏览器的跨域规则。

方案二：hls.js 亲手集成

想把播放行为握在自己手里，可以引入开源库 hls.js，十几行代码搭出完整链路：

<video id="player" controls></video>
<script src="https://cdn.jsdelivr.net/npm/hls.js"></script>
<script>
  const video = document.getElementById('player');
  const src = 'https://example.com/live/index.m3u8';
  if (Hls.isSupported()) {
    const hls = new Hls({ maxBufferLength: 30 });
    hls.loadSource(src);
    hls.attachMedia(video);
    hls.on(Hls.Events.ERROR, (_, data) => console.warn(data.details));
  } else if (video.canPlayType('application/vnd.apple.mpegurl')) {
    video.src = src; // Safari 等原生支持 HLS 的环境
  }
</script>

代码先探测 MSE 可用性：支持就走 hls.js，否则退回原生 HLS，两套环境一并覆盖。

方案三：本地播放器兜底

碰到源站不开跨域、网页端怎么调都黑屏的流，换 VLC 这类桌面播放器往往一次成功——它们运行在浏览器沙箱之外，没有 CORS 顾虑，还能补 Referer 等请求头。先确认链接本身是好的，再回头调网页方案，是效率最高的排查路径。

落地前的三点提醒

  • 跨域：网页方案要求源站返回 Access-Control-Allow-Origin，这是最常见的失败点，具体诊断见 六步定位问题根源。
  • 协议一致：HTTPS 页面引用 HTTP 流会被浏览器拦截，两边必须同协议。
  • 编码兼容：H.264/H.265 视频搭配 AAC 音频兼容性最好，冷门编码可能出现无声或花屏。
